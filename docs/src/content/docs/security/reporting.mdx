---
title: Security
description: How to report a security vulnerability in UPM.
---

Security is a shared responsibility. If you believe you've found a vulnerability, report
it privately rather than posting it publicly.

## Report privately

Do **not** open a public issue or pull request for a security vulnerability. Instead,
contact the maintainers privately. Include:

- What the problem is and where it lives.
- How to reproduce it, and the version affected.
- Any proof-of-concept.
- Whether the issue is already public.

You will get a reply within a few business days, and the fix is credited in the release
notes.

## Scope

This covers the UPM source code, documentation, and released artifacts — remote code
execution, privilege escalation, injection, broken auth, secret exposure, and
supply-chain issues.

## Public-safety rule

This repository is public. It must never contain credentials, customer data, internal
conversations, or undisclosed commercial information. If you find a secret committed
here, treat it as a security incident and report it rather than spreading it.
