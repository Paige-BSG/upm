The **short-term goal** is to validate, in the open, an AI-native data-service ops control
plane: an in-product agent that takes intent, a domain harness that is the security
contract, and deterministic operators that execute the change.

## Where the project is now

- **Foundation (done)** — the public repository skeleton, the Nimbus documentation site,
  the agent LLM wiki, and the branch / pull-request and governance contract. This is the
  groundwork, not a product phase.
- **Phase 1 — BackupProof (Spec v0.2)** — the first product technical validation: an agent
  → plan → signed approval → backup → isolated restore → evidence slice, on the
  three-layer architecture. It proves the control-plane design; it is a validation, not a
  shipped product. Program detail in [Phase 1 — BackupProof](/architecture/phase-1-backupproof).
- **Parallel discovery track** — market interviews and requirements-validation writing
  continue separately from BackupProof; they are not a repo phase.
- **Later** — release the control-plane components with docs that describe them
  accurately, then add the product-code gates and wire the docs / wiki / secret checks
  into CI.

## Principles

- **AI-native, deterministic** — the agent reasons and orchestrates; deterministic
  operators change data. The agent is never allowed past the harness to kubeconfig, a
  shell, or raw database credentials on its own.
- **Truthful** — pages describe what exists, not an imagined shipped product.
- **Public-safety rule** — source, docs, decisions, and release evidence are public;
  credentials, customer data, internal conversations, and undisclosed commercial
  information never enter the repo.
