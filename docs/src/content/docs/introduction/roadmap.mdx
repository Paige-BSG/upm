title: Roadmap
description: The short-term goal for UPM and how the project gets there.
---

The **short-term goal** is to validate, in the open, an AI-native data-service ops control
plane: an in-product agent that takes intent, a domain harness that is the security
contract, and deterministic operators that execute the change.

## Phases

1. **Public skeleton** — establish the public documentation and the agent LLM wiki, and
   lay down the branch/pull-request contract. This is what exists today.
2. **Knowledge base** — ingest the external resources and open-source components the
   product references or compares against (agents, operators, package charts, datastore
   engines) into `llm-wiki/`, each pinned and license-aware.
3. **Phase 0 slice** — the first agent → plan → approval → backup → isolated restore →
   evidence loop, on the three-layer architecture. This validates the control-plane
   design; it is a proof, not a shipped product.
4. **Product code** — release the control-plane components, with the project docs
   describing them accurately.
5. **Automation** — add product-code gates and wire the existing checks into CI once
   there is code to test.

## Principles

- **AI-native, deterministic** — the agent reasons and orchestrates; deterministic
  operators change data. The agent is never allowed past the harness to kubeconfig, a
  shell, or raw database credentials on its own.
- **Truthful** — pages describe what exists, not an imagined shipped product.
- **Public-safety rule** — source, docs, decisions, and release evidence are public;
  credentials, customer data, internal conversations, and undisclosed commercial
  information never enter the repo.
