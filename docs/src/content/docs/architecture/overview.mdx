This page is the **intended** design for UPM. The product code is still being refactored
and has not been released into this public repository, so treat this as the direction,
not a description of a shipped artifact.

## Core idea

UPM manages databases and middleware on Kubernetes. The intended shape is a set of
Kubernetes-native controllers (operators) that reconcile a declarative description of
the data infrastructure — the database or middleware engine, its version, and its
topology — into running, upgraded, and operable resources.

## Components

- **unit-operator** — manages single database or middleware instances (a "unit") on
  Kubernetes. Likely a `CustomResourceDefinition`-driven controller that provisions a
  stateful workload and writes/reads its configuration.
- **compose-operator** — manages composed or multi-unit deployments, wiring multiple
  units together into a single logical service.
- **upm-packages** — package and Helm chart definitions that make the components
  installable and upgradeable.

## How it fits

The reference implementation is [upmio](https://github.com/upmio); UPM is a thorough
refactor of it, not a branch fork. [KubeBlocks](https://github.com/apecloud/kubeblocks)
is the comparison baseline.

## Where the detail lives

The LLM wiki (`llm-wiki/` in this repository) pins the external resources and
open-source components these operators will depend on — operators, CRDs, Helm, and the
datastore engines. Read it for the pinned, license-aware technical ledger. This docs
site is the human-oriented summary.
